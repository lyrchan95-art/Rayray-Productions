# Idea2Proto: MVP1 "Idea to Prototype"

A mobile-first PWA that turns a spoken (Cantonese-first) idea into a shareable single-file prototype.
Next.js 16 (App Router) · Auth.js v5 · `node:sqlite` · GLM + DeepSeek behind a `ModelProvider` interface.

## Product spec

Idea2Proto turns a spoken or typed idea (Cantonese, English or 中英夾雜) into a clickable mobile prototype, then helps the founder shape and test it. This section describes the product as built; the skills and agents lists below are regenerated by `node scripts/build-artifact.mjs`, so they never drift from the code.

**Who it is for.** Indie founders and small teams in Hong Kong who want to see an idea on a phone before spending on design or engineering.

**Core flows**
- **Quick build (default).** Idea → one fast structuring call (title, one-liner, user, core interaction, 3–4 screens, palette) → the shell is written locally from the palette, instantly → screens are generated two at a time and appear live. Target: first real screen in well under a minute.
- **Idea Studio (deep mode).** For complex ideas: a groomed blueprint (personas, screens, branching decisions, facts, risks), a style board and optional market research feed the same staged build.
- **Iterate.** On a staged product, a change is planned first (quick call) and only the affected screens, or the shared CSS, are rewritten. Structural changes fall back to one whole-document edit.
- **Check agent.** Every version is measured locally at 390px (layout, targets, contrast, labels, reachability, errors). Automatic fixes run only for hard failures; the expert review is one tap away.
- **Agents.** Validator, prototype sprint and launch kit, each with at most two steps; independent steps run side by side.

**Preview.** A separate panel, independent of the chat: docked beside it on desktop, full screen on phones with one tap back to the chat. Chat activity never reloads the prototype; it reloads only when its content changes.

**Memory.** Each idea keeps a README (spec, screens, decisions, style, market notes, change log, versions) that is regenerated after every change, shown in the preview's README tab, downloadable, embedded in downloaded HTML, and sent to the model as project memory on chats, edits and agent runs. Ideas are saved on the device and, when the viewer is signed in, to their private account storage, so a cleared browser or another device keeps them.

**Durability.** In-flight work survives a locked screen or a dropped connection (see "Durable jobs" below).

## Run it

```bash
cd idea2proto
npm install
cp .env.example .env.local   # every key is optional for local dev
npm run dev                  # http://localhost:3000
```

With no model keys the app runs on a **deterministic mock provider**, so the whole loop (capture, spec, generate, iterate, publish, journal) works offline. Set `DEV_LOGIN=1` for one-click sign-in. Without SMTP, magic links are printed to the server log.

Requires Node ≥ 22.5 (built-in SQLite).

## Known gaps / next steps

- **Cantonese STT is unverified.** STT goes to any OpenAI-compatible `/audio/transcriptions` endpoint (GLM-ASR by default, `language=yue`). It has not been tested against real speech. Benchmark it on real founder recordings before beta.
- **Real-model quality is unverified.** No GLM/DeepSeek keys were available, so every end-to-end run used the mock provider. `evals/<skill>.json` holds assertion-based cases, but there is no runner yet for live providers.
- **Router eval is 118 items, not 200**, and was written alongside the heuristics. Expect lower accuracy on real user traffic. Grow it from logged turns.
- **FPS** isn't supported by Stripe. The UI says "contact us" for now. A local PSP integration is needed for AlipayHK/FPS-native flows.
- Publishing defaults to **Pro-only** (`FREE_CAN_PUBLISH=0`), per PRD 4.9. Consider enabling it for beta users, because the 60-second "shareable" metric needs it.
- SQLite fits a single instance. Move to Postgres before running multiple instances.
- The PICS text is a draft. Have counsel review it.

## OpenRouter

Set `OPENROUTER_API_KEY` to switch on live models through one key. OpenRouter serves every role that has no direct `GLM_API_KEY` / `DEEPSEEK_API_KEY` (chat, cheap and vision → GLM slugs, code → DeepSeek slug). The slugs are set in `.env.example`; check them against openrouter.ai/models. In a cloud session, `openrouter.ai` also has to be allowed in the environment's network settings.

## Test artifact

`artifact/idea2proto-live.html` is a standalone, client-only version of the loop for testing on claude.ai. Artifact pages can't make outside network requests, so it runs on the artifact's built-in model access, not GLM/DeepSeek, and keeps ideas in the viewer's browser.

## Imported skills and the quality gate

`skills/*.md` holds the design skills the app injects into generation prompts (head designer, frontend designer, Fable discipline, world weaving, Cantonese copywriter) and the `ux-audit` workflow. `node scripts/build-artifact.mjs` bakes them into `artifact/idea2proto-live.html` from `artifact/idea2proto-live.src.html`. Edit the `.src.html` template, never the built file.

Quality gate, for every artifact turn: design, then measure (a hidden 390px render checks runtime errors, overflow, tap targets, contrast, labels, plus static checks), then an expert review that returns a score, issues and tips, then at most one auto-fix, accepted only if it measurably improves the result. Quick tweaks get the measurement only; first builds and re-audits also get the expert review. Tips (upload assets, decisions, details to add) appear under the result. Uploaded images are referenced as `asset:ID` tokens so image bytes never go into prompts.

Not yet ported to the Next.js app (`src/`): skill packs, the gate, tips and assets.

## UI standard

The artifact's own interface follows the head-designer constitution: three tones (jade, vermilion, paper) plus ink with everything else mixed from them, no gradients or pills, radii of 8px or less, one directional shadow on the mic, paper grain, a left-weighted hero, and rows and rules instead of bordered cards. Tap targets are 44px or more and text meets AA contrast.

## Output first, check in the background

A prototype is delivered the moment generation finishes. While it writes, a work log shows the steps (spec read, skills applied, a live phase detected from the stream, elapsed time). The check agent then measures the version locally in the background (no model call). It only asks the model for a fix when an automated check hard-fails; the expert review (UX audit + tips) runs when you tap "Re-check" or "Fix", so it never slows a build. A fix is saved as a new version and offered with a "switch" button; the version on screen never changes underneath you, and the preview iframe is never reloaded by the check.

## Idea Studio (deep mode)

For complex ideas, the spec review offers **Deep · Idea Studio** (the default for longer descriptions). Instead of building straight away, two model calls run in parallel and fill in progressively:

- **Blueprint** (`skills/idea-grooming.md`): archetype (service, commerce, tool, content, marketplace, dashboard, game), value proposition, what is different, specific personas, a screen flow, 3-5 real trade-off decisions, facts to confirm, assets, risks and a definition of done.
- **Style board** (`skills/style-board.md`): two tones, paper, ink, a curated type pairing, radius, density, motion and a signature detail, shown as a live specimen. A contrast guard deepens tones that would be illegible, keeping hue and saturation.

**Branching:** every decision option carries effects (add or remove screens). Tapping an option reshapes the flow immediately; core screens can never be removed. A readiness score shows what is still open.

**Build:** the blueprint, style tokens, archetype build pattern and (on first builds) a reference scaffold from `skills/premium-craft.md` go into the prompt. The product is multi-screen (`data-screen` / `data-go`), and the check agent walks every screen, verifies each blueprint screen exists and is reachable, and measures craft: 4px spacing rhythm, number of font sizes, families, corner radii and hues. The scaffold scores 100; a deliberately cheap page fails craft.

Bad or missing model output falls back to a usable template, so the Studio never dead-ends.

## Market research assistant

`skills/market-research.md` is a workflow skill with its own section in Idea Studio (and a call to action in the Skills tab). It has **no web access**, so it is built around that limit: markets are sized by method with labelled assumptions rather than invented numbers, competitors are named only when certain (otherwise shown as a category), every price is a range with a basis and confidence, URLs are stripped from model output, and each claim comes with a "how to verify" step. Output is a structured brief: segments, alternatives (including WhatsApp groups and spreadsheets), price anchors, demand signals with copyable search queries, Hong Kong factors, ranked risks, a go/pivot/stop verdict and three moves for the week. A failed run shows an error and stores nothing. The findings feed re-grooming and the build prompt, always labelled as unverified estimates, and the section warns when the idea has changed since the research was run.

## Durable jobs and staged builds (screen lock, slow output)

Every model call in the live artifact runs as a **job** saved to storage with its partial output.

- **Screen locks / tab hidden:** the stall watchdog notices a stream that stopped while the viewer's own device was hidden, and asks the model to *continue* from the saved text (the seam overlap is stitched out) instead of restarting. Auto-resume happens only for that case, at most 3 attempts. A Screen Wake Lock is requested while building when the browser allows it.
- **Service errors / cold reloads:** no silent retries. A Resume bar appears (also inside the full-screen phone preview) and one tap continues from what is saved; Discard drops the job.
- **Staged build** (3+ screens, from a Studio blueprint or the quick spec): the shell is written locally from the style tokens (no model call), then screens two at a time, each its own call. The version is the checkpoint, so a resume redoes only unfinished screens; a screen that fails twice gets an honest placeholder and a "retry these screens" row. Check-agent fixes rebuild only the offending screen.
- **Tuning:** thresholds live in `localStorage["i2p.tune"]` (`awayStream`, `graceStream`, `awayJson`, `graceJson`, `stuck`, in ms).
- **Edits** to a staged product are planned with a quick call and rewrite only the affected screens (or the shared CSS); structural changes fall back to one resumable whole-document call.
- **Not covered:** agent-run progress is not persisted across reloads; account sync needs a signed-in viewer (otherwise ideas stay on the device); the Next.js app does not have these features.
